# Setup: online booking (Cloudflare + Telegram + Google)

The site is still generated by `src/build.py`, but booking now has a small backend:

| Part | What it does | Cost |
|---|---|---|
| **Cloudflare Pages** | Hosts the site and runs the API in `functions/` | Free plan |
| **Cloudflare D1** | Stores rides (deleted automatically after 30 days) | Free plan |
| **Telegram bot** | Sends every new ride to Adam's phone with buttons: *✅ 10 min*, *❌ Odrzuć*, *📍 Jestem na miejscu*… | Free |
| **Google Maps Platform** | Address search, GPS → address, map, route distance/time, Google reviews | Free monthly allowance per service; needs a billing account |

How a ride works:

1. The customer enters pickup (typed or **Tu jestem** GPS) and destination, chooses **Teraz** or **Na później** and taps the button.
2. `POST /api/rides` checks the input, calculates the route and price **on the server**, saves the ride and sends it to Adam on Telegram.
3. The customer lands on `/przejazd/?id=…`, which checks the status every few seconds.
4. Adam taps a button in Telegram. Telegram calls `/api/telegram`, the ride status changes, and the customer's page updates (with a sound and vibration).
5. If Adam doesn't answer a "now" ride within 3 minutes, the customer is asked to call. After 15 minutes the request expires.

Without the backend (for example on GitHub Pages or a plain local preview), the form still works: it shows a pre-filled WhatsApp / SMS message instead.

## 1. Telegram bot (5 minutes, on Adam's phone)

1. In Telegram, open **@BotFather** → `/newbot` → pick a name (e.g. *Taxi Knurów Kursy*) and a username ending in `bot`.
2. BotFather replies with a **token** like `123456:ABC-…`. That's `TELEGRAM_BOT_TOKEN`.
3. Don't send `/start` yet. That happens in step 4.

## 2. Google Maps Platform

1. Go to <https://console.cloud.google.com>, create a project and add a **billing account** (Google requires a card; normal use of this site stays within the free monthly allowance).
2. **APIs & Services → Library**: enable **Maps JavaScript API**, **Places API (New)**, **Geocoding API** and **Routes API**.
3. **Credentials → Create API key** twice:
   - **Browser key**: Application restriction *Websites*. Add your Cloudflare address, e.g. `https://taxi-knurow.pages.dev/*` and `https://*.taxi-knurow.pages.dev/*` (previews), plus `http://localhost:8788/*` for local tests. Add `https://YOUR-DOMAIN/*` and `https://www.YOUR-DOMAIN/*` when you have a domain. Don't use `*.pages.dev`, which would let every pages.dev site use your key. API restriction: Maps JavaScript API, Places API (New), Geocoding API.
     Put it in `src/data.py` → `GOOGLE_MAPS_BROWSER_KEY`. It's visible in the page source by design; the website restriction is what protects it.
   - **Server key**: no application restriction. API restriction: Routes API, Places API (New), Geocoding API. Address suggestions and GPS → street address run through this key on the server. This becomes the Cloudflare secret `GOOGLE_SERVER_KEY`, so **never** put it in the code.
4. **Map ID**: Google Maps Platform → *Map management* → *Create map ID* (JavaScript, Vector). Put it in `src/data.py` → `GOOGLE_MAP_ID`.
5. **Place ID** of the business (for reviews): find "Taxi Knurów Adam Mączka" in the [Place ID Finder](https://developers.google.com/maps/documentation/javascript/examples/places-placeid-finder). This becomes `GOOGLE_PLACE_ID`.
6. Recommended: **Billing → Budgets & alerts**, set an alert at e.g. 10 €.

Note: Google returns at most **5 reviews** and chooses them itself. The site keeps those with 4–5 stars and enough text, best first. Reviews are cached for 12 hours.

## 3. Cloudflare Pages

1. Create a free account at <https://dash.cloudflare.com>.
2. **Storage & Databases → D1 → Create database** named `taxi-knurow`. The table is created automatically on first use.
3. **Workers & Pages → Create → Pages → Connect to Git** → choose the GitHub repo and branch.
   - Build command: `pip install jinja2 && python3 src/build.py`
   - Build output directory: `dist`
4. After the first deploy, open the project → **Settings**:
   - **Bindings → Add → D1 database**: variable name `DB`, database `taxi-knurow`.
   - **Variables and Secrets** (type *Secret*):

     | Name | Value |
     |---|---|
     | `TELEGRAM_BOT_TOKEN` | token from BotFather |
     | `TELEGRAM_WEBHOOK_SECRET` | any long random string (letters/digits) |
     | `ADMIN_KEY` | another long random string (password for the setup page) |
     | `GOOGLE_SERVER_KEY` | server key from step 2 |
     | `GOOGLE_PLACE_ID` | place ID from step 2 |
     | `TELEGRAM_CHAT_ID` | added in step 4 |
     | `MAX_BOOKINGS_PER_HOUR` | optional (type *Text*): bookings allowed per device per hour, default 8. Set e.g. `100` while testing, then delete it |
     | `AERODATABOX_KEY` | optional: flight times. Sign up at rapidapi.com, subscribe to **AeroDataBox** (free Basic plan), copy your `X-RapidAPI-Key` |
5. **Deployments → Retry deployment** so the settings take effect.
6. Custom domain: **Custom domains → Set up a custom domain**.

## 4. Connect Adam's Telegram

1. Open `https://YOUR-SITE/api/admin/setup?key=YOUR_ADMIN_KEY` in a browser. This connects the bot to the site and lists what's still missing.
2. On Adam's phone, open the new bot and send `/start`. The bot replies with **Twój chat ID: 123456789**.
3. Add that number as the secret `TELEGRAM_CHAT_ID` in Cloudflare, then redeploy.
4. Open the setup URL again. `"ready": true` means it's done, and Adam receives a test message.
5. Make a test booking on the site and tap the buttons in Telegram.

## 5. Before going live (check with Adam)

In `src/data.py`:
- `TARIFF`: start fee and price per km for routes outside the price list (currently an estimate: 9 zł + 3 zł/km, minimum 15 zł).
- `ZONE_KM`: how far from Knurów centre the surcharge zones A (+10 zł) and B (+20 zł) reach.
- `COORDS`: approximate coordinates of airports, spas and stations. A route ending within `match_km` of one of them gets the fixed price-list fare.
- `NOW_WAIT_MIN`: minutes before the customer is asked to call.

Then rebuild (`py src/build.py`). The build also regenerates `server/config.js`, so the server uses the same prices.

## Local testing

```bash
py src/build.py
npx wrangler pages dev dist --d1 DB=taxi-local \
  --binding TELEGRAM_BOT_TOKEN=... --binding TELEGRAM_CHAT_ID=... --binding TELEGRAM_WEBHOOK_SECRET=test --binding ADMIN_KEY=test
```
Telegram can't reach `localhost`, so button taps don't work locally unless you simulate them with a POST to `/api/telegram` (header `X-Telegram-Bot-Api-Secret-Token`).

## Instrukcja dla kierowcy (Telegram)

Każde zamówienie przychodzi jako wiadomość z adresami (kliknij adres → nawigacja w Mapach Google), telefonem klienta, ceną, lotem i przyciskami:

- **Kurs TERAZ**: wybierz, za ile minut będziesz (**✅ 5 / 10 / 15 / 20 / 30 min**) albo **❌ Odrzuć**. Klient widzi taksówkę jadącą po drodze i odliczanie.
- **REZERWACJA**: **✅ Potwierdź rezerwację** albo **❌ Odrzuć**. W dniu kursu kliknij **🚕 Wyjeżdżam – 10/20/30 min**.
- W drodze: **⏱ +5 min**, jeśli się spóźnisz; **📍 Jestem na miejscu**, gdy czekasz pod adresem.
- Na miejscu bot wysyła nową wiadomość: **▶️ Klient wsiadł – rozpocznij kurs** (albo **❌ Klient nie przyszedł**).
- W trasie: **🏁 Zakończ kurs**. Klient dostaje prośbę o opinię w Google.
- Jeśli klient anuluje, przychodzi osobna wiadomość **🚫 Klient anulował**.

**Lokalizacja na żywo (zalecane):** w czacie z botem: 📎 → Lokalizacja → **„Udostępniaj lokalizację na żywo”** (np. na 8 godzin).
Wtedy klient widzi, ile km jesteś od niego, a gdy dojedziesz pod adres, bot **sam zapyta**, czy jesteś na miejscu – wystarczy potwierdzić.
Po dojechaniu do celu bot zapyta, czy zakończyć kurs.

> Po aktualizacji strony otwórz raz `…/api/admin/setup?key=ADMIN_KEY` – to włącza odbieranie lokalizacji na żywo.
